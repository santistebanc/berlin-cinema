# Domain docs

This repository uses a single-context domain layout.

## Before exploring

Read GLOSSARY.md at the repository root when present.
Read relevant architecture decisions under docs/adr/.

If GLOSSARY-MAP.md is introduced later, follow its
pointers to the glossaries relevant to the task.

When domain documents are absent, proceed silently.
Create them lazily when terminology or architectural
decisions are actually resolved.

## Vocabulary

Use the glossary's defined terms in specifications,
issues, implementation discussions, and tests.

When a needed concept is missing, check existing project
terminology before proposing a glossary addition.

## Architecture decisions

Respect relevant ADRs. Explicitly identify any proposal
that contradicts an existing ADR and explain why that
decision should be reconsidered.
